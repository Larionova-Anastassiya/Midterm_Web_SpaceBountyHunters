# Space Bounty Hunters — Midterm Practical Assignment

A REST API for tracking wanted space criminals and recording bounty-hunting attempts. Built using **Kotlin 2.0.21 + Ktor 3.0.3 + PostgreSQL 17 + JDBC**, matching my previous Mystical Manor project. **No frontend** (not required).

## Quick start (Windows 11, Docker Desktop)

1. Start Docker Desktop.
2. Open CMD in the project root.
3. Create `.env` from `.env.example`:

```cmd
   copy .env.example .env
   ```

4. Edit `.env` and replace `POSTGRES\_PASSWORD` with a unique password. Do not commit `.env`.
5. Start both services:

```cmd
   docker compose up --build -d
   docker compose ps
   ```

6. Check API: `curl http://localhost:8082/api/health`.
7. Import `postman/SpaceBountyHunters.postman\_collection.json` into Postman and run requests **01–14 in order**. The collection uses `baseUrl=http://localhost:8082` and saves `huntId` automatically.

> If host port 8082 is occupied, change `APP\_PORT` in `.env` and update Postman's `baseUrl` accordingly. Internal backend port remains 8080.

## Architecture

* `backend`: custom multistage Dockerfile, Ktor/Netty HTTP server on internal port 8080.
* `db`: `postgres:17-alpine` on private Docker network; not published to host.
* `bounty-network`: Docker Compose network; backend connects to database at hostname `db`.
* `bounty-data`: named volume at `/var/lib/postgresql/data`; survives `docker compose down` and recreation.
* `.env`: runtime configuration, excluded from Git and Docker build context.

## Database models

### `wanted\_criminals` (one criminal -> many hunts)

|Column|SQL type|Description|
|-|-|-|
|id|BIGSERIAL PK|Unique identifier|
|name|VARCHAR nullable|Real name can be unknown|
|nickname|VARCHAR UNIQUE|Criminal alias|
|reward|BIGINT|Non-negative bounty|
|latitude, longitude|DOUBLE PRECISION nullable|Coordinates; supplied as a pair|
|location\_note|TEXT nullable|Alternative location text|
|difficulty|INTEGER CHECK 1..10|Difficulty|
|armed, has\_crew, escape\_master|BOOLEAN|Criminal attributes|

### `hunt\_logs`

|Column|SQL type|Description|
|-|-|-|
|id|BIGSERIAL PK|Unique identifier|
|criminal\_id|BIGINT FK|Existing criminal; ON DELETE CASCADE|
|success|BOOLEAN|Whether target was captured|
|notes|TEXT|Encounter description|
|created\_at|TIMESTAMPTZ|Automatically generated by PostgreSQL|

At initial database creation, `initialize()` creates tables and seeds **5 criminals and 10 hunt logs**. Seeds are conditional, so restarting containers does not overwrite saved changes.

## API documentation

All endpoints accept both forms **with and without a trailing slash**.

|Method|Endpoint|Description|Success|
|-|-|-|-|
|GET|`/api/health`|Backend health|200|
|GET|`/api/criminals/`|List/filter/sort criminals|200|
|GET|`/api/criminals/{id}/`|Criminal details|200|
|GET|`/api/hunts/`|List hunts, optionally filter by criminal\_id|200|
|GET|`/api/hunts/{id}/`|Hunt details|200|
|POST|`/api/hunts/`|Record a hunt|201 + Location header|
|PATCH|`/api/hunts/{id}/`|Update success and/or notes|200|
|DELETE|`/api/hunts/{id}/`|Delete hunt|204|

### Criminal filters (can be combined)

* `min\_reward`: non-negative integer, inclusive
* `max\_reward`: non-negative integer, inclusive
* `armed`, `has\_crew`, `escape\_master`: `true` or `false`
* `sort`: `reward` (ascending) or `-reward` (descending)

Example:

```http
GET /api/criminals/?min\_reward=5000\&armed=true\&sort=-reward
```

### Hunts filter

```http
GET /api/hunts/?criminal\_id=1
```

### Create hunt

```http
POST /api/hunts/
Content-Type: application/json

{"criminal\_id":1,"success":false,"notes":"Target escaped through an asteroid field."}
```

`created\_at` is **not** accepted from the client; PostgreSQL generates it automatically. Response contains `id`, `criminalId`, `success`, `notes`, `created\_at`.

### Partial update

```http
PATCH /api/hunts/11/
Content-Type: application/json

{"success":true}
```

You may send only `success`, only `notes`, or both. A missing/invalid criminal reference returns 400; invalid ID formats return 400; nonexistent resource IDs return 404; successful delete returns 204.

## PostgreSQL verification

```cmd
docker compose exec db psql -U bounty\_user -d space\_bounty
```

```sql
SELECT COUNT(\*) FROM wanted\_criminals;
SELECT COUNT(\*) FROM hunt\_logs;
SELECT id, nickname, reward, difficulty FROM wanted\_criminals ORDER BY reward DESC;
SELECT h.id, c.nickname, h.success, h.notes, h.created\_at
FROM hunt\_logs h JOIN wanted\_criminals c ON c.id = h.criminal\_id ORDER BY h.id;
```

Exit psql with `\\q`.

## Persistence test

```cmd
docker compose down
docker compose up -d
```

Data remains because `bounty-data` is a named volume. **Do not use `docker compose down -v`** unless you intentionally want to erase the database and reinitialize the seeds.

## Troubleshooting

```cmd
docker compose config -q
docker compose logs --tail=100 backend
docker compose logs --tail=100 db
docker compose ps
```

If you change the password in `.env` after the database was first initialized, the stored PostgreSQL user's password is not automatically changed. Keep the original password or change the password inside PostgreSQL. For a disposable new database only, `docker compose down -v` recreates the volume (deletes all data).
